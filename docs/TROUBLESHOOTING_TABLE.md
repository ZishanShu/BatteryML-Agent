# Troubleshooting

Problems a user can meet while following the protocol, in the order of the steps
that produce them. Each row names what is seen, why it happens, and what to do.

Throughout, `<DATASET>` is a dataset name such as `MATR`, and every command is
run from the repository root.

| Step | Problem | Possible reason | Solution |
| --- | --- | --- | --- |
| Setup | `pip install yaml` fails with *"Could not find a version that satisfies the requirement yaml"* | The name used to import a package and the name used to install it are different strings. `import yaml` comes from the distribution `pyyaml`; `import sklearn` comes from `scikit-learn`. | Install from the requirements file, which lists installation names, rather than from names read out of an error message: `pip install -r requirements.txt`. |
| Setup | Commands work in one terminal and not another | Two Python environments are present and only one has the dependencies. `pip` and `python` in the same shell can also belong to different environments. | Run `python -m scripts.verify.check_environment`. It reports the interpreter in use and every declared package as installed or missing, and it runs even when nothing else does. Install with `python -m pip install ...`, which always targets the interpreter you are running. |
| Setup | `ModuleNotFoundError: No module named 'scripts.verify'` | Another installed package also provides a top-level `scripts` module and takes precedence over the one in this repository. | Run the command from the repository root. If it persists, the environment contains a conflicting `scripts` package; use a clean environment for the protocol. |
| Preprocessing | The command prints `Successfully processed 0 batteries` and appears to succeed, but no data is produced | The preprocessor looks for raw files by name pattern in the top level of the raw directory only. If the files sit inside a subdirectory, are still inside an archive, or are named differently than expected, nothing matches and there is nothing to convert. | The wrapper now stops with a message naming the directory it searched and the patterns it searched for. Compare those patterns with your filenames. Most often the files are one level too deep: move them directly into `data/raw/<DATASET>/`. If they are archived, extract them first. |
| Preprocessing | `error: the input format 'BIOLOGIC' is declared as supported but is not implemented` | The command line accepts eight cycler formats, but only `ARBIN` and `NEWARE` have a reader. The remaining six are declared upstream without an implementation. | Export the data from your cycler software to a format that is implemented, then preprocess that. The message lists the formats available in your installation. |
| Preprocessing | `AssertionError: Input path not exist: data/raw/<DATASET>` | The raw data has not been placed where the command expects it. | Create `data/raw/<DATASET>/` and put the raw files in it. Public datasets can be fetched with `batteryml download <DATASET> data/raw/<DATASET>`. |
| Preprocessing | Several datasets need preprocessing and one failure stops the work | Each dataset is preprocessed by a separate command. | Use `python scripts/preprocess_sweep.py`, which preprocesses every dataset that has raw data, continues past failures, writes a per-dataset log to `logs/preprocess/`, and summarises the outcome in `logs/preprocess/sweep_report.csv`. It can be re-run safely: datasets already processed are skipped. |
| Preprocessing | A `data/processed/<DATASET>/` directory exists but is empty | A preprocessing run that produced nothing left the directory behind, because the directory is created before the conversion is attempted. | This is the most dangerous state in the workflow, because it does not look like an error: training checks that the directory exists, finds it empty, and then trains on no data. Run `python -m scripts.verify.run_all --only DATA-02`, which lists every such directory. Either preprocess the dataset, or remove the empty directory with `rmdir data/processed/<DATASET>` — which will refuse if the directory is not in fact empty. |
| Training | `AssertionError: data/processed/<DATASET>` | Training reads processed data, never raw. That dataset has not been preprocessed. | Preprocess it first: `python scripts/preprocess_sweep.py --only <DATASET>`. |
| Training | `unrecognized arguments: --config` | The configuration file is passed as a positional argument, not as an option. | Write the path directly after `run`: `python batteryml_web/core/run_batteryml_cli.py run configs/.../matr_1.yaml --workspace runs/demo --train --eval --device cpu --seed 0`. |
| Training | The command prints a directory path and exits without training | `--train` and `--eval` are both required. Without them the run only reports where results would be written. | Add `--train --eval` to the command. |
| Training | `ModuleNotFoundError: ... 'batteryml' is not a package` | `bin/batteryml.py` was run directly. The `bin` directory shadows the package of the same name. | Always go through the wrapper: `python batteryml_web/core/run_batteryml_cli.py ...`. |
| Training | `<Model> is not registered to Models!` | The configuration names a model whose code was never loaded. | Run `python -m scripts.verify.run_all --only REG-01`, which lists every model that is available and reports whether the extension mechanism is consistent. If the model lives in `batteryml_web/models/`, its module must also be listed in that package's `EXTENSION_MODULES`. |
| Training | A configuration is rejected before the run starts | The configuration is checked against the models, splitters and feature extractors actually available, and against the data it declares, before anything executes. | The message names the offending field. To check every configuration at once, without needing data present, run `python -m scripts.verify.run_all --only VAL-01`. |
| Training | `ConvergenceWarning: lbfgs failed to converge` | An iterative model reached its iteration limit before the fit settled. | The result is not final and should not be reported. Raise `max_iter` in the model section of the configuration and re-run. If the warning persists at a much larger value, the problem is the conditioning of the data rather than the iteration budget. |
| Results | Re-running after preprocessing gives exactly the same numbers as before | The assembled dataset is cached, and the cache key is computed from the configuration only — not from the contents of the processed data. Re-preprocessing therefore does not invalidate it. The log line `Load datasets from cache ...` is the only sign. | Delete the cache before trusting a number after any preprocessing run: `rm -rf cache/`. |
| Results | Two runs of the same configuration give different numbers | Either the seed differs, or the cache was cleared between runs while the underlying data changed. | Pass `--seed 0` explicitly on both runs and clear `cache/` before each. With the same configuration, the same seed and the same data, the reported metrics are identical. |
| Any step | A command fails and it is unclear which layer is at fault | The wrapper distinguishes its own checks from failures inside the pipeline by exit code. | `0` succeeded; `1` the pipeline itself failed and printed its own error; `2` a precondition failed before anything ran (an unavailable format, or a mis-declared extension); `3` preprocessing ran but produced no data. |
| Any step | You want to know whether the installation is sound before running anything | A set of checks inspects the environment, the datasets, the configurations and the registries without training, evaluating, downloading, or writing into `data/`. | `python -m scripts.verify.run_all`. It prints one line per check and writes a full report to `runs/verify/verification_report.json` alongside a readable summary. Add `--only <ID>` to run a single check. |
